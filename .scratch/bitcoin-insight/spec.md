## 껍데기·프리미티브 규칙

사이트에는 두 갈래 규약이 있다. 아래 표는 설명형 페이지용이다.

```text
데이터 대시보드   h1 없음 · 전폭 · 합니다체
  자산 현황 · 경제 차트 · 원자재 차트 · 비트코인 차트 · 비트코인 네트워크

설명형 페이지     h1 · max-w-5xl · 해라체
  인사이트 7개 · 프로토콜 10개 · 화폐 · 기업 · 부동산
```

대시보드에 h1을 붙이거나 설명형 페이지를 전폭으로 바꾸면 각자의 부류와 어긋난다. 티켓 20 참조.

새 설명형 페이지를 만들거나 기존 페이지를 손볼 때 이 표를 따른다.

| 항목                     | 규칙                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 페이지 골격              | `AppHeader` + `PageMain` + `max-w-5xl` + h1 + 인트로 `p.text-sm/relaxed`                                                     |
| h1                       | 단정형 또는 질문형 한 문장. 논지가 논쟁적이면 인트로 첫 문장에서 주장의 출처를 밝힌다                                        |
| 탭                       | 내용이 실제로 갈릴 때만 쓴다. 억지로 만들지 않는다                                                                           |
| 탭 라벨                  | 번호 접두사 없이 명사구                                                                                                      |
| `SectionIntro`           | 탭·섹션마다 하나. 탭 없는 페이지도 섹션 구분에 쓴다                                                                          |
| 가상 수치 고지           | 페이지 인트로 마지막에 `수치는 개념 이해용 예시다.` 한 문장. 실데이터 탭이 섞인 페이지는 해당 탭의 `SectionIntro`에만 넣는다 |
| `IllustrativeDisclaimer` | 실제 위험 예측으로 오독될 여지가 큰 곳만. 현재 `bitcoin-quantum`·`illicit-funds`                                             |
| `StatCard` / `Metric`    | 조작·진행에 따라 값이 변하면 `StatCard`, 상수면 `Metric`                                                                     |
| 지표 그리드              | 기본 `grid-cols-2 sm:grid-cols-3`. 서로 접을 수 없는 독립 지표가 넷일 때만 4열                                               |
| 판정·결과 문구           | `Metric`이 아니라 `StatusBanner`                                                                                             |
| tone 어휘                | `good` / `bad` / `accent` 셋만                                                                                               |
| 캐스케이드 시각화        | `CascadeStage`. 정렬 축 오름차순 정렬이 전제다                                                                               |
| BCRA                     | `src/lib/bcra.ts`를 거친다. 이득 ÷ 비용 방향만 쓴다                                                                          |
| 슬라이더                 | 범위가 여러 자릿수를 덮으면 `scale='log'`                                                                                    |
| 기본값                   | 첫 화면에서 페이지가 설명하려는 긴장이 이미 보여야 한다. 주 컨트롤이 결과를 바꾸지 못하는 상태로 시작하지 않는다             |

## 중복 지도

각 개념에 주인 페이지를 하나 정하고 나머지는 한 문장 + 링크로 축약한다. UI가 실제로 같을 때만 공용 컴포넌트로 추출한다.

### D1. 공격 이득 ÷ 비용 비율 (심각)

같은 비율을 세 시뮬레이션이 계산하는데, 이름과 방향이 제각각이다.

| 위치                              | 계산                       | 이름      | 방향          |
| --------------------------------- | -------------------------- | --------- | ------------- |
| `softwar/abstract-vs-physical`    | 자원 가치 ÷ 탈취 비용      | BCRA      | 낮을수록 안전 |
| `softwar/softwar-vs-hardwar`      | 적의 공격 이득 ÷ 투사 권력 | BCRA      | 낮을수록 안전 |
| `bitcoin-game-theory/attack-game` | 공격 비용 ÷ 이중지불 이득  | 이름 없음 | 높을수록 안전 |

`/softwar` 안에서 1번 탭과 3번 탭이 같은 모델을 파라미터 이름만 바꿔 두 번 돌린다. 거기에 `/bitcoin-game-theory`는 같은 비율을 뒤집어 이름 없이 쓴다. 독자가 두 페이지를 오가면 "이 숫자가 크면 안전한가 위험한가"가 뒤집힌다.

주인: 개념 정의는 `/softwar`. `/bitcoin-game-theory`는 비트코인 채굴이라는 구체 사례로 남기되 비율 방향과 이름을 맞춘다.

### D2. 51% 공격 (심각)

| 위치                              | 관점                                                  | 그룹     |
| --------------------------------- | ----------------------------------------------------- | -------- |
| `chain-reorg` (3탭 전체)          | 기술: 재구성이 왜 일어나고 확인 수가 왜 안전을 주는가 | 프로토콜 |
| `bitcoin-game-theory/attack-game` | 경제: 왜 합리적 공격자는 안 하는가                    | 인사이트 |
| `mempool` 채굴풀 카드 한 줄       | 풀 점유율 50% 초과 위험 언급                          | 인사이트 |

관점이 실제로 갈리므로 양쪽을 남긴다. 문제는 세 곳이 서로를 전혀 참조하지 않는다는 것이다. `chain-reorg/attack-scope`는 "51%로도 못 하는 것"을 다루는데 `attack-game`은 그 범위 제약을 언급하지 않아, 게임이론 페이지만 읽으면 51%가 무엇이든 할 수 있다고 오해할 여지가 있다.

주인: 기술은 `/chain-reorg`, 경제는 `/bitcoin-game-theory`. 상호 링크를 넣는다.

### D3. 캐스케이드 시각화 UI (중간)

`adoption-cascade`와 `hodl-dilemma`의 렌더 블록이 약 60줄 동일하다.

```text
Card
├─ RoundControls (props 8개 동일)
├─ 축 라벨 좌/우 (낮음 ↔ 높음)
├─ AgentGrid orientation='column' highlight=...
├─ 격자 읽는 법 설명문
├─ Legend 행 + 오른쪽 끝 보조 설명
└─ Sparkline cursor=round heightClass='h-12'
Metric 그리드 3칸
완료 배너
```

ADR-0001이 두 시뮬레이션이 같은 구조(전역 신호 + 임계값 오름차순 정렬)를 공유한다고 이미 못박았다. 시각화도 같은 구조이므로 공용 컴포넌트로 추출한다.

`softwar/primordial-economics`도 `AgentGrid` + `RoundControls` + `Sparkline`을 쓰지만 정렬 축이 임계값이 아니라 투사력이고 격자 읽는 법이 다르다. 추출 대상에 넣을지는 S1에서 실물을 보고 판단한다.

### D4. 채택 (중간)

| 위치                                   | 무엇을 채택이라 부르나                                           |
| -------------------------------------- | ---------------------------------------------------------------- |
| `bitcoin-game-theory/adoption-cascade` | 임계값을 넘긴 행위자가 채택으로 전환. `CONTEXT.md`에 정의됨      |
| `bitcoin-volatility/volatility-engine` | 슬라이더 라벨 `채택 추세 (drift)`. 실제로는 성공 확률 p의 표류항 |
| `bitcoin-history` 시장·채택 탭         | 실제 역사 사건                                                   |

`volatility-engine`의 `채택 추세`는 용어집이 정의한 채택률과 다른 것을 가리킨다. 용어 충돌이다.

주인: 채택 모델은 `/bitcoin-game-theory`. `volatility-engine`의 라벨은 채택이라는 말을 쓰지 않는 것으로 바꾼다.

### D5. 비트코인 가격은 무엇인가 (중간)

같은 사이트가 가격에 세 가지 모델을 쓰는데 서로를 언급하지 않는다.

| 위치                               | 가격 모델                    | 답하는 질문                  |
| ---------------------------------- | ---------------------------- | ---------------------------- |
| `bitcoin/rainbow-chart`            | Power Law 공정가치           | 장기 추세 대비 지금 어디인가 |
| `bitcoin-volatility/two-regime`    | 성공 확률 p × 터미널 가격    | 왜 이렇게 출렁이는가         |
| `bitcoin-game-theory/hodl-dilemma` | 매도 압력에 따른 반사적 하락 | 폭락은 어떻게 증폭되는가     |

중복이 아니라 층위가 다르다. 삭제하지 않고, 각 페이지가 자기 모델이 답하는 질문을 한 문장으로 밝혀 독자가 충돌로 읽지 않게 한다.

### D6. 채굴 경제 (낮음)

`attack-game`(장비 단가·전기 요금·정직 채굴 수익), `grid-battery`(채굴 부하 용량), `mempool`(해시레이트·블록 보상), `block-mining`(프로토콜 그룹, 난이도 조정)이 채굴을 각각 다른 층위에서 다룬다. 서술 중복은 없다. 링크만 검토한다.

### D7. 개념 시연 고지 (낮음)

가상 수치를 쓰는 페이지가 6개인데 고지 방식이 셋으로 갈린다: `IllustrativeDisclaimer` 배너(`quantum`, `illicit-funds`), 인트로 괄호 문구(`grid-battery`), `models.ts` 주석에만 있고 화면에는 없음(`game-theory`, `softwar`, `volatility`). 합의된 규칙대로 인트로 한 문장으로 통일하고 배너는 `quantum`·`illicit-funds`만 남긴다.

## 용어집 재조직 판단

`CONTEXT.md`는 현재 `시뮬레이션` / `채택 게임` / `홀더 게임` 세 절이다. 앞 절은 페이지를 가로지르는 공통 어휘고 뒤 두 절은 `/bitcoin-game-theory` 한 페이지의 탭 어휘다.

공통 절에 들어갈 자격이 있는지 실제 사용처로 확인했다.

| 용어       | 쓰는 시뮬레이션                                    | 페이지                     |
| ---------- | -------------------------------------------------- | -------------------------- |
| 행위자     | 채택 캐스케이드, 홀더 딜레마, 자연의 파워 프로젝션 | 게임이론, 소프트워         |
| 라운드     | 위 셋 + 변동성 엔진                                | 게임이론, 소프트워, 변동성 |
| 궤적       | 채택 캐스케이드, 홀더 딜레마                       | 게임이론                   |
| 캐스케이드 | 채택 캐스케이드, 홀더 딜레마                       | 게임이론                   |

행위자와 라운드는 세 페이지를 가로지르므로 공통 절이 정당하다. 궤적과 캐스케이드는 아직 한 페이지 안에 머문다. 다만 티켓 04로 캐스케이드 시각화를 공용 컴포넌트로 뽑으면 이 둘도 공통 어휘가 된다.

결론: 합의된 (b)안대로 간다. S1에서 `## 공통` 절로 재조직하고 `## 권력 투사` 절을 추가했다. S2에서 `## 체제 전환`과 `## 전력망` 절을 더했다. `정렬 축`과 `도태`는 세 시뮬레이션이 공유하게 되어 공통 절에 새로 넣었다.

원래 계획: `## 공통`을 두고 행위자·라운드·궤적·캐스케이드를 넣는다. 나머지는 페이지가 아니라 개념 영역별 절로 쓴다. 새로 필요한 절은 `## 권력 투사`(BCRA, 추상 권력, 물리 권력, 파워 프로젝션), `## 체제 전환`(체제, 성공 확률, 터미널 가격, 실현 변동성), `## 자금 추적`(홉, 믹서, 출구, 가명성)이다. 실제 집필은 각 섹션에서 그 페이지를 다룰 때 한다.
