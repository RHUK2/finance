# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 읽어야 하는지 정리한다.

## 탐색 전에 읽을 것

- 루트의 `CONTEXT.md`
- `docs/adr/`: 작업하려는 영역과 맞닿은 ADR을 읽는다

파일이 없으면 아무 말 없이 진행한다. 부재를 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`를 통해 호출됨)이 용어나 결정이 실제로 정리되는 시점에 필요한 만큼만 만든다.

## 파일 구조

이 저장소는 단일 컨텍스트다.

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

컨텍스트가 여러 개로 갈라지면 루트에 `CONTEXT-MAP.md`를 두고 컨텍스트별 `CONTEXT.md`와 `src/<context>/docs/adr/`를 둔다.

## 용어집의 어휘를 쓴다

출력이 도메인 개념을 지칭할 때(이슈 제목, 리팩터링 제안, 가설, 테스트 이름) `CONTEXT.md`에 정의된 용어를 그대로 쓴다. 용어집이 피하기로 한 동의어로 흘러가지 않는다.

필요한 개념이 아직 용어집에 없다면 그건 신호다. 프로젝트가 쓰지 않는 언어를 지어내고 있거나(재고할 것), 실제로 빈 곳이 있거나(`/domain-modeling`용으로 기록할 것) 둘 중 하나다.

## ADR 충돌은 드러낸다

출력이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시적으로 드러낸다. 예: "ADR-0007(이벤트 소싱 주문)과 상충함. 다만 다시 논의할 만한 이유는…"
